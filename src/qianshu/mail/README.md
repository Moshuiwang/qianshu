# Trace #12 邮箱入口

## X7 单封试跑

常驻入口 `python -m qianshu` 在指定 `--mail` 时启用收信轮询，与飞书长连接共用验收窗口和汇报群。
通过 `--env-file` 指定私有 `.env`，默认读取当前目录的 `.env`。
`MAIL_HOST`、`MAIL_USER`、`MAIL_PASSWORD`、`MAIL_APPROVER`、`MAIL_TEST_MARKER` 缺任一项时启动失败。
`MAIL_PORT` 可选，默认 993。常驻入口也从同一配置文件读取可选的
`MAIL_FOLDER`、`MAIL_SENT_FOLDER` 和 `MAIL_PRIVATE_DIR`。

轮询线程启动即检查一次，每轮结束后等待 60 秒。验收窗口结束或常驻服务退出时发出停止信号，
阻止下一轮轮询和新的汇报发送。在途 I/O 仍受原有超时约束。同一邮件指纹在汇报状态库中只登记一张卡片，
发送重试沿用同一飞书请求 UUID。邮件正文复用群申请的解析和校验，卡片只展示来源、审批结论、
处理状态和计数。常驻入口当前传入 `approval_judge=None`，审批显示「不确定，交人工」。
0.1.0 的 X7 按 Trace 合同修订 r5 只验收信、解析和出卡片，审批判断器顺延 #38。

库调用方可自行使用 `qianshu.mail.poll_once(config, process)`，也可调用
`run_polling(config, process, stop)`，由 `threading.Event` 控制结束。库调用的连接参数
`MAIL_HOST`、`MAIL_PORT`、`MAIL_USER`、`MAIL_PASSWORD` 和可选的 `MAIL_FOLDER`
沿用 `load_config`。调用方在配置映射中提供 `MAIL_APPROVER`（产品负责人邮箱）
和 `MAIL_TEST_MARKER`（本次验收生成的一次性随机标记，
使用 ASCII 字母、数字、下划线或短横线）。两个入口都可选传 `MAIL_PRIVATE_DIR`，
默认为当前目录下的 `.private/`。
通过 IMAP `LIST` 中的 `\Sent` 属性定位已发送文件夹。服务器未提供该属性时使用
配置映射里的 `MAIL_SENT_FOLDER`，该项也缺失时轮询报错。
多个文件夹带 `\Sent` 时，使用与 `MAIL_SENT_FOLDER` 匹配的候选。无法选定时，
审批按「不确定」交人工，申请正文照常交接。

收件箱筛选按摘要头排除带 `In-Reply-To` 或 `References` 的回复。恰有一封原件的发件人
和主题标记均匹配时才读正文。去重记录保存在私有目录，测试标记一旦绑定就沿用该绑定。
处理回调接收 `(正文, 当前是否已获审批, 去重指纹)`，
正常返回后记为已交接。回调报错或进程在交接结果落盘前中断时，下一轮可能重试同一指纹。
下游有副作用时要按该指纹幂等处理。`poll_once` 返回本轮的 `PollResult`。
使用 `run_polling(..., on_result=回调)` 时，每轮成功轮询都会把 `PollResult` 交给该回调。
调用方通过 `PollResult.approved` 收到正文交接后才到达的审批结果。

审批从已发送文件夹读取产品负责人的关联回复。优先匹配 `In-Reply-To`，该字段缺失时
检查 `References` 最后一项。两个入口都接受可选的 `approval_judge`，它只接收作者本次回复的文字，
返回 `ApprovalDecision` 的四类结论之一。所有关联回复及其正文版本都判为 `APPROVE`（同意）
才算已获邮件审批。「带条件」的回复交人工处理。缺少可识别正文、遇到归属不明的回复头、
容器或分隔线，或 HTML 引文容器之后还有任何非空文字时，直接按「不确定」交人工并跳过判断器。
判断器异常、超时或缺失时，
也按「不确定」处理。审批结果为未获审批时，申请正文照常交接。
两个入口都可用 `approval_judge_timeout` 设置每轮判断的等待上限，默认 5 秒。
两个入口共用进程内唯一的判断线程名额。已有判断线程在运行时，本轮审批按「不确定」处理。
试跑窗口和标记发放按 Trace #12 合同执行。调用方对外仅交接获准的测试邮件正文。
真实试跑验收时，编排者可在前后分别用 `qianshu.mail.imap.connect` 只读打开两个文件夹，
用 `seen()` 回读各自的已读 UID 集合并比对，只公开比对结果。

## X8 历史样例查找

编排者按合同在冻结候选两层审核通过后运行。凭据从 `--env-file` 指定的私有配置读取，
默认 `.env`。另外从进程环境提供 `MAIL_HISTORY_SUBJECT`，可选配置 `MAIL_PRIVATE_DIR`。
已发送文件夹也按 `\Sent` 属性定位，回退值 `MAIL_SENT_FOLDER` 从进程环境读取。
选择范围用 IMAP 内部收件日期，包含起始日，截止日不含。
按 UID 从新到旧选择最多 10 封主题匹配的邮件，并查找其已发送关联回复。

```sh
python -m qianshu.mail.history --env-file /path/to/private.env --since 2000-01-01 --before 2000-02-01
```

输出位于私有目录下新建的 `mail-history-*/samples.json`，内含申请和回复的信头及文字正文。
导出前对两个文件夹各做一次读取前后的已读 UID 集合比对。命令成功时只输出申请和关联回复封数。

## 残余风险

- **多词本地化回复头**：回复头识别只认单个词的字段名（如 `From:`、`发件人:`、`Von:`），带空格的多词字段名（如韩文客户端的「보낸 사람:」）不会被当成回复头。审批人回复时若只摘录了这样一行头和含「同意」的旧文，旧文会进入判断器。0.1.0 的邮件审批人只有一人，使用网易企业邮箱中文界面，按守望者裁定作为残余风险接受，由收口块的真实测试邮件实测一次兜底。**改为多审批人或开放其他邮件客户端之前，必须先修好这一条。**

## 运行环境与解析约定

- 邮件解析一律显式使用 `email.policy.default`（`BytesParser`、`BytesHeaderParser`），不依赖标准库的默认策略。
- 曾发现的版本差异：同一封折行的 `Message-ID`（字段名后直接换行、值在续行），Python 3.12.3 解析出的值带前导空格，3.12.13 不带，导致 3.12.3 下回复无法关联到申请、审批判断器不被调用。现只去掉值开头的空格与制表符，仍要求只有一个该字段、整个值符合格式；ID 内折行、单字段多个 ID、重复字段一律拒绝。
- 本仓运行环境的 Python 补丁版本固定（见仓库 `.python-version`），升级须先评估。
