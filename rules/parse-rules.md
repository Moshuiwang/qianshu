# 字段取值规则

依据产品文档 6.2、6.3 及解析协议 2、3。逐字段提取原文状态、值、证据及必要说明，默认、换算、查表和业务派生由程序处理。

| 字段 | 提取要求 |
| --- | --- |
| `policy_name` | 只填原文明确采用的本条政策名称，逐字保留名称本身，并给一段恰好等于名称的引文。同句如有业务限制，在受影响字段保留该限制和原文证据。待定、询问报歧义，相互冲突报冲突，带条件报带条件。确实没写才报原文未写，由程序按政策类型处理 |
| `policy_short_name` | 可选。公开政策需要拼名时，提取原文已写明的本条活动或优惠短名，并附逐字证据。原文没写短名就报「原文未写」，不要自拟。区分本次活动、背景案例、备选和限定。无法确认短名时按状态协议报告。国家代码和生效日期由程序拼接 |
| `maintain_mutual_exclusion_group` | 明确维护填「是」，明确不维护填「否」。辨别询问、条件、否定、相反要求和条款归属。归属或适用范围不清时报对应的不确定状态。R7 只在原文未写且归属清楚时默认「是」。概念验证期明确为「否」交人工 |
| `country` | 适用于本条的国家。区分本条适用地、共享限定、背景国家和缩写的其他含义。尽量使用规范国家名 |
| `company`、`company_keyword` | 分别提取明示的公司主体与可查表的原文关键词或代号。对线索给出完整词项列表及各自证据。区分明示主体、线索、背景及其他政策的公司，单独声明各字段的状态 |
| `policy_type` | 原文明示的「定向政策」或「公开政策」。没有明示时报告原文未写，程序按 R8 从确定的标签状态派生。原文有冲突时保留相关候选 |
| `start_date`、`end_date` | 分别提取 YYYY-MM-DD 的申请起止日期。前言只可供起止日期取证。识别日期的限定对象（国家或公司）及其适用政策。前言、批次共享的有效申请周期可作依据，无标题的单条政策也可使用自己的申请周期。排除作废、参考、罚停、标签有效期等日期。日期适用对象不清时在受影响的字段报告不确定状态。日期格式或用途有多解时报歧义，保留候选 |
| `benefit_type` | 以交易条件和所得权益判定。充值时长后延长同包观看是「赠送时长」，充值时长后获得更高档权益是「升级权益」，按金额取得一定观看时长是「特价优惠」。区分「充一个月送一个月」与「充一个月的钱看两个月」。同段有两种解释、选择待定或适用对象不清时，报歧义并给有证据的候选。跨行引用完整条件，区分否定的金额、参考原价和实际交易条件 |
| `trigger_once` | 明确只触发一次填「是」供人工确认，明确可多次填「否」，未写由程序默认「否」 |
| `cancel_on_downgrade` | 明确取消填「是」，明确不取消填「否」，例如有效条款说明「不限制升降包」。辨别仅为询问、条件或其他时期的说明。未写时赠送时长请人在卡片确认，升级权益和特价优惠按产品规则默认 |
| `recharge_days`、`gift_days`、`watch_days`、`penalty_days` | 分别提取充值时长、额外赠送时长、总可看时长、罚停时长。赠送时长和升级权益填前两项，特价优惠填总可看时长。罚停涉及时单独提取。以 `quantity` 和 `unit`（「天」或「月」）表示，中文数值转为对应整数，程序按每月 30 天换算。时长范围、多个备选或含义不清时保留候选并报歧义。明确无罚停时可报确定的 null 并给引文 |
| `amount_mode`、`recharge_amount`、`tariff`、`tariff_multiplier` | 适用于特价优惠。明确固定实付金额用「自定义」，明确以节目包资费为计算依据用「节目包资费」。金额量级按原文换算为数值，排除原价、被否定的金额和参考金额。金额或方式存在范围、多解或待选时保留候选并报歧义。按资费计算时，`tariff` 分别给有证据的 `base_package`（资费所属基本包）、`price_plan`（价格计划）、`unit`（资费单元）、`version`（原文未明确版本时填 null，由程序查有效版本），另报明确的资费倍数。未直接写出的计算金额报原文未写 |
| `after_offer`、`after_offer_package` | 适用于升级权益和特价优惠。只看优惠到期时的明确去向，填「恢复原包」或「指定节目包」。选「指定节目包」时另给明确的目标包。区分申请期间的受赠包和到期后的目标包。到期去向有多个合理解释时报歧义，未写时由程序默认恢复原包 |
| `forbid_package_change` | 适用于升级权益和特价优惠。优惠期间明确不允许换包填「是」，明确允许换包填「否」。单独判断本字段，区分优惠期间换包与降包取消。未写由程序默认「是」 |
| `first_recharge_day_only` | 只在特价优惠明确要求首次充值当天时填「是」。未写留空，明确无此限制可报确定的 null 并给引文。不把首充当天、优惠触发次数和客服处理次数当作同一条件 |
| `repeat_bonus`、`effective_multiplier` | 分别提取是否允许多买多送和明确的生效倍数。区分许可、禁止、条件及询问，区分资费倍数和生效倍数。未写时程序分别默认「是」、1。明确非 1 生效倍数交人工 |
| `user_tags` | 按原样提取完整标签名，区分标签归属、当前采用与备选。原文明示面向全体且无需标签时给确定的空列表和证据 |
| `packages` | 本条标题指定的当前包只填一行。区分标题的当前包、活动中的受赠目标、到期去向和仅允许充值的包。赠送时长同包时由程序取得其 `_copy`。升级权益和特价优惠提取明确的受赠目标。无独立标题、标题存在多个包或标题与正文有冲突时保留候选并报待确认 |
| `user_scope` | 用自由文本概括适用用户，保留本条适用的逐字摘录。适用范围无法确认时报对应的不确定状态 |
| `approval_url` | 只提取明确属于本批申请的归档文档网址。区分参考链接、以前的存档和不适用于本条的局部说明。原文明示本批无存档链接时，报确定的 null 并保留引文。未写时按原文未写报告，后续按 R9 补齐 |
| `approval_attachments` | 不把业务附件当作审批件。没有适用的审批件表述时报告原文未写，由程序按已定规则留空 |

## Trace #12 · sc6b 公司默认值与关键词

每条政策对应唯一公司。每份申请只加载一次受信表。UTF-8 CSV 或 TSV 表头依次为「国家」「关键词」「公司内部编号」「公司显示名」。每国至多一行默认公司，默认行关键词留空。按 R10 对确定的国家及适用线索查表，并与明示公司主体核对。读完本字段适用材料后线索报「原文未写」，或确定的线索查无关键词命中时，可用该国唯一默认公司。多命中、主体冲突、国家不明、表无效或不能唯一确定公司时交人工。文件编辑、旧表格式和行级日志见产品文档 6.2。
