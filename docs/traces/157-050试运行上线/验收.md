### 2b 部署读回

部署时从转交的全机私有租约目录读取 `status.json`。核对 `alive`、`state`、`sampled`、`backlog`、`unconfirmed`、`manual_checks`（人工核对）与 `pending_notices`（通知待核），采样过期按失联处理。审批租约位于同目录的 `consumer.lock`。停机后先核对原进程组已空，再在该私有目录执行 `flock -n consumer.lock true`，退出码 0 表示此时可取得并释放租约。保留租约文件及私有登记库供后继服务接管。

开关或名单每次变更后，用同一私有登记库执行 `python -m qianshu --trial-publish-switches <0600开关文件> --state <私有目录>/trial-050.sqlite3`。发布事务关闭旧授权区间，登记本次修订。文件发生外改或未发布时，点击转人工。子进程按已认证回调核对来源、卡片及点击人，点击后即时核验群成员（时限 2 分钟）。仅私有名单内且查询在群时有效，超时或查询失败给固定提示。私有开关 MAIL_TRIAL_MEMBER_CHECK_SECONDS 默认 120，范围 1 至 120 秒。

### 2c/2d 部署

以下命令只用飞书转交配置，不读业务凭据；带业务凭据的环境拒绝运行，统一用 `env -i PATH=/usr/bin:/bin LANG=C.UTF-8 <仓库>/.venv/bin/python -I -m qianshu …` 执行。每条执行后都读回并打印状态。

- 初始化存档授权库（仅首次，已有库不覆盖）：`--trial-init-archive-ledger <私有目录>/archive-ledger.sqlite3`。读回库存在与 `grants` 表结构，结果为「已初始化」或「已存在，未覆盖」。
- 停写位：`--trial-halt status --state <私有目录>/trial-050.sqlite3` 读回；`--trial-halt set|clear --state <同上> --reason <原因>` 置位或清除，原因写入登记库留痕。读回当前值、最后一次变更的动作、原因与 UTC 时刻。回读写错时程序已自行置位并记下关建单开关的请求，守望者关建单开关、停查，查清并经产品负责人同意后才清除。
- 销清人工移交：`--trial-release-handoff <登记> <版本> <条目> <政策名指纹> --state <同上> --reason <原因>`。**此命令只在产品负责人当场明确同意时由守望者执行。** 登记 ID 与政策名指纹（按归一政策名算，取自 `--list-recovery` 的 `order_handoff` 行）都与登记库对上才执行；执行前回显该条状态与指纹（不回显政策名原文），执行后读回；任一不符即拒绝、非 0 退出、零写入。销清只作用于该条登记：不清同名其他登记的移交，只释放该条自己占用的在途槽；同名有多条未销清移交时，前后回显逐条列出（只含登记号与指纹）。
