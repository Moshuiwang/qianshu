## 4. 验收标准

- 可观察完成标准逐条见[验收.md](验收.md)（E-1～E-8）。
- 证据等级要求：#95 L4（文档档 CI）+ G1 登记；#96 L4 + 实跑；解析类（#55 #56 #58 #69 #70 #82）L4 + 新量尺三次运行报告；发版部署 L5 并回读版本。未达目标等级时，降级关闭须守望者裁定，缺口登记到 040 对应工作项。
- **预批口径（量尺与协议要点；#95 写成长期文档，只可收紧不可放宽）**：
  - **字段结果的记录**：每个字段分开记四样——模型给的原文状态（确定 / 原文未写 / 歧义 / 冲突 / 带条件 / 缺证据）、程序派生的取值、取值来源（原文 / 默认规则 / 查表派生）、是否需要人工确认。「程序不得升级状态」指：模型状态为歧义、冲突、带条件或缺证据时，程序不得产出来源为「原文」且无需确认的值；模型状态为「原文未写」且产品文档有默认规则时，程序按规则写默认值、标来源「默认」并在卡片注明，这是合规行为；产品文档要求确认的情形（如赠送时长的降包、R7 归属不清）记「需人工确认」。
  - **金标与可判定性**：只用冻结时已标注的内容。每篇申请冻结「是否已枚举全文全部政策」标记；每个字段沿用冻结分母，并按冻结审定记录区分「原文可推出」与「原文不能推出」。没有这些标记的部分，评分记「未知」，不计入对错。
  - **配对**：每篇申请内，把草稿与冻结的人工配置按业务键打分（国家 / 公司、优惠类型、节目包、充值与赠送天数或金额、用户标签、起止日期重叠），取全局最优一一配对；同分时按冻结顺序决定，并记「同分」。分数与阈值在 #96 合并时冻结（看候选结果之前）。配不上的人工配置记「漏条」；多出的草稿在「已枚举全文」的申请里记「多条」，在其余申请里记「未知（可能是未抽中的政策）」。证据位置不参与配对。
  - **配对抽核**：独立抽核清单覆盖配上、漏条、多条或未知三类（各约 10 / 5 / 5 对），另加全部「同分」配对（最多 5 对），由调研者逐对判对错；配上类正确率 ≥ 95%、其余各类无系统性错配才冻结阈值。
  - **字段评分**：每个可比字段归为正确确定（含合规默认）/ 错判确定（无需确认的值与金标不同）/ 多问（「原文可推出」却需人工确认）/ 合理需确认（「原文不能推出」或产品文档要求确认）/ 缺失（未配上）/ 未知。
  - **主指标「可比字段全对率」**（严格定义写入 #95）：配上且全部可比字段均为「正确确定」的政策数 ÷ **本套数据自身的冻结政策数**（冻结考题 148、盲测集按实际冻结数）。它是「卡片零修改可确认率」的代理：节目包、用户范围等分母为 0 的字段不在其中，真正的零修改率在这些字段有完整标注前报「不可判定」。辅指标：安全可确认率（配上且无错判确定）、错判确定率（错判确定项 ÷ 可比字段项）、多问率、漏条与多条数、回复解析失败篇数。
  - **旧量尺**（严格位置对齐）照旧输出唯一对齐 / 未对齐 / 歧义，只作诊断，不作门槛。
  - **盲测集**：从冻结考题**未用过的申请**中抽取——按申请正文指纹整篇排除考题的 86 篇，并排除与之正文近似重复的申请（归一化正文指纹相同即排除）；按同一分层规则冻结约 60 条，实际条数、分层和指纹登记在 #94；盲测集与节目包补充集按申请正文指纹互斥，同一封申请不得同时进入两者。审定方式同考题集（审定者 + 另一模型交叉核对，分歧逐条记录），含全文枚举标记与字段可判定性。存私有目录；实施卡与审核卡写明禁止读取。盲测集只在 G2 基线与发版候选终验上运行，不用于迭代或选候选。终验盲测不达门槛时不得改代码后再用同一盲测集复验：报守望者，选择「如实降级发版」或「挪 040 并另冻结一份复验集」。**残余风险**：Codex 沙箱不限读取，只能靠卡面禁令与回收时核查日志里的读取路径（已裁定 2）。
  - **节目包补充集**（#70 完成标准要求先补标注）：冻结考题的节目包分母为 0，另从未用过的申请中抽约 20 条含具体包名或档位的政策，审定行集合（包名、受赠包）与全文枚举标记，冻结规则同盲测集、可给实施者看；只在 G2 与终验运行。门槛在 G2 由守望者确认、候选运行前冻结；默认：写明具体包名的政策中行集合完全一致 ≥ 50%，只写档位的政策 100% 判需人工确认，错判确定 0。做不到补标或不达门槛时由守望者裁定降级，并登记缺口。
  - **波动计法**：放行用的运行（G2 基线、W1 放行、发版终验）冻结考题各 3 次、盲测集 2 次，报均值与最小–最大；诊断用的运行（W2 各卡、修复后）只跑 1 次，只用来发现问题，不作提升或不劣的结论。同一协议版本内只改程序的版本，对已存回复离线重放（无波动）。「提升成立」= 候选三次最小值 > 基线三次最大值；「不劣于」= 候选三次最大值的错判确定率 ≤ 基线三次最大值。
  - **跨协议版本的比较**：W1 改了输出结构，旧版无法解析新回复，因此 W1 与 main 的比较只用各自三次真实运行的量尺结果，不做同一回复的重放对比；同一回复的重放对比只在相同协议版本之间做（如 W2 候选对 W1 合并后），并报告实际成功解码、可比较的样例数，不可比的样例不得计为「无退化」的证据。
  - **门槛**（DG2 在 G2 基线出数后由守望者确认数值；默认按下式）：冻结考题主指标三次均值 ≥ 基线均值 + max(10 个百分点, 2 × 基线波动幅度) 且「提升成立」；错判确定「不劣于」基线；候选的全部放行运行回复解析失败 = 0（基线不适用，已导入的重跑有 2 篇失败，照实计）；冻结变体族上程序侧不变量 100% 成立；盲测集主指标提升（百分点）≥ 冻结考题提升的一半，否则判过拟合，报守望者。
  - 判据拿不准时默认：判「需人工确认」或「未知」，不算正确。
- **审核标准（两类，#93 约束 6）**：
  - **安全边界类，一条就拦**（凡涉及程序如何处理模型输出的条目，须能用固定模型回复 + 预期程序行为复现，即问题出在程序而不是模型理解；改动 17 处安全边界、凭据或真实数据入库这类从差异即可确认的，直接拦）：改动 17 处安全边界；模型状态为歧义、冲突、带条件或缺证据时程序产出无需确认的原文值；证据核对失败（摘录不在原文、越出本条范围、只是子串）仍无需确认；默认值用于「原文未写」以外的状态；冻结变体族上程序侧不变量不成立；同协议版本下同一份已存回复重放，main 上需确认的字段在候选上成了错判确定；新增按关键词、标点、换行做的语义判断（属格式或查表的须在 PR 说明里逐处标类别）；真实入口行为偏离 main 的约定（如建单字段集合）；凭据或真实数据进入仓库、日志、Issue、PR。
  - **理解类，按比例评**：模型理解错了（某种说法认错、归属认错），不是拦截理由，也不增加审核轮次；只由放行运行的比例判（门槛见上）。审核中新举的理解类反例只登记到 #94 的诊断清单，留作后续版本扩充变体族，本版不滚动加入分母。实施者不得为单条理解类反例在程序里补字面规则，只能改提示词、字段说明或协议。
- 既定条款：正式验收在已升版本号的提交上做，前提由脚本核对。
- 既定条款：用户可见断言（部署回读）双通道观测：进程与版本回读 + 服务启动日志。
- 既定条款：证据只认仓库 / GitHub 留痕——审核结论、回归计数、裁定当天落对应 Issue 或 PR；真实数据与原始回复只留私有目录，公开只写计数与指纹。
- 既定条款：产品负责人真人验证块：本版无。
