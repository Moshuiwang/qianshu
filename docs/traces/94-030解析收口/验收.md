## 批终链（全绿才进下一阶段）

本机受影响测试绿 → 冻结候选跑本机全量 → 同协议版本下已存回复重放出两把量尺（只改程序时）或按合同 §5 运行表跑 X1（改提示词或输出结构时）→ Codex 审核者审一次 → 修复 ≤ 2 轮、定向复核 ≤ 2 次 → 推送开 PR → CI 完整档 → 合 main。整合阶段：发版候选冻结 → S-3-2 终验 → 必要时修复包并重建候选 → 发版 PR 两层审核，脚本核对终验 SHA、依赖、配置、量尺与数据指纹和最终候选一致（不一致则按合同 §6 重新取得终验证据）→ 守望者合并并推标签 → 部署回读。冻结后回填：候选 SHA `________`；门禁 run `________`。

## 未验证层级（收口时如实列）

- 真实建单（含测试单）本版不做：#69 #70 的建单字段组装只到 L3 / L4。
- 回归是本地真实数据上的离线评测，不等于真实邮件进来后的线上旅程（收信本版关闭）。
- 盲测集隔离只靠卡面禁令与回收核查（合同裁定项 2）。
- 冻结考题中节目包、用户范围的分母为 0：主指标是「可比字段全对率」，真正的「卡片零修改可确认率」报「不可判定」；节目包只在补充集上出数，用户范围只有合成测试。
