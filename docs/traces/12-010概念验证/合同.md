## 4. 验收标准

- **可观察完成标准**：逐条见[验收.md](验收.md) E-1～E-8，每条写明被判的值由谁写入。
- **证据等级**：L1 已分析 / L2 已改代码 / L3 本地测试通过 / L4 CI 通过 / L5 已部署 / L6 真实旅程验证 / L7 回源确认。关键路径（E-1、E-3、E-4）目标 **L6**；其余见验收.md。未达目标等级的降级关闭由守望者裁定，缺口登记到下一里程碑的工作项。
- **预批口径**：
  - 比对一致性：日期按日比，不按时刻；文本字段去首尾空白后逐字比；可多选字段按集合比。
  - 机器人输出「不确定」的字段在比对里单列，既不算错也不算对，计数报出。
  - 判据拿不准时默认：待人工复核。
- 正式验收在已升版本号的提交上做：#15 的版本号 PR（只改 `pyproject.toml`、`uv.lock`、`CHANGELOG.md`）排在收口块**之前**合并；收口块在该提交上执行；之后的记录 PR 只改文档，推标签前用 `git diff --stat` 读回证明。X5 不因发版重跑。
- 用户可见断言双通道观测：群卡片截图（真人看到的），对照机器人日志或平台回读。
- 证据只认仓库与 GitHub 留痕。真实数据产物只落服务器私有目录，Issue 只写计数、比例与指纹。
- **产品负责人真人验证块只放两处**：
  - **前置块**（实施最前，一次给齐）：飞书事件订阅保存（#8）；#9 的三项输入；Codex 云端审核接入本仓（#14）；ops 请求若需本人操作。
  - **收口块**（Trace 最后，一次排完）：群里 @千树Bot 发样例（#8 / #2）；发一封带测试标记的申请邮件（#9，X7）；确认就绪自检、通知审批人与配置人后执行 X6 → X5（#11）。
  - 每块先由守望者出就绪自检，一次一条指令。

## 5. 成本预算

- **完整门禁**（本机 `uv run pytest` 全量 + 该 head 的 CI）：≤ 30 次，即 14 个 PR × 约 2 次，另余 2 次。
- **时间窗**：合同合并起 ≤ 48 小时机器工作时间，不含等产品负责人与等 Ops。硬期限：无。
- **CI 计划**：
  - 本地门禁：实施卡只跑受影响测试；冻结候选跑一次全量。
  - GitHub CI 预计触发约 40 次，即 14 个 PR × 约 3 次推送，含 1 次草稿转正式。单次时长：文档档约 10 秒，取 2026-11-18 本仓当天全部 run（≥ 10 个，各 8–18 秒）实测；完整档未知，首个代码 PR 实测后回写时间校准表第 5 行。
  - 硬超时 10 分钟（工作流 `timeout-minutes`）。
  - 同机多 Trace 的完整门禁：本仓同一时刻只 1 个 PR 跑全量。
- **额度弹性**（原上限 / 守望者可自行追加）：
  - 子代理人次 40 / +15；
  - Codex 调用 70 / +30；
  - 云端审核每 PR ≤ 3 轮 / +1；
  - 完整门禁 30 / +10。
  - 修复类分列：审核修复轮按每卡 2 轮估（高风险 #7、#11、#14 按 3 轮）；冻结前补项 ≤ 5；CI 暴露的修复 ≤ 6；真机试跑轮 X2 ≤ 3、X3 ≤ 2；X5 只 1 次、至多 1 条单（失败即停，报守望者）。
- **收口记录 PR 预留**：完整门禁 1、内审 1。合并条件：文档档 CI 绿 + 同源自查 + 云端审核（若已启用）已处置。
