## 4. 验收标准

- **可观察完成标准**：逐条见[验收.md](验收.md) E-1～E-6，每条写明被判的值由谁写入。
- **证据等级**：L1 已分析 / L2 已改代码 / L3 本地测试通过 / L4 CI 通过 / L5 已部署 / L6 真实旅程验证 / L7 回源确认。关键路径（E-1、E-3、E-4）目标 **L6**；其余见验收.md。未达目标等级的降级关闭由守望者裁定，缺口登记到下一里程碑的工作项。
- **预批口径**：
  - 比对一致性：日期按日比，不按时刻；文本字段去首尾空白后逐字比；可多选字段按集合比。
  - 机器人输出「不确定」的字段在比对里单列，既不算错也不算对，计数报出。
  - 判据拿不准时默认：待人工复核。
- 正式验收在已升版本号的提交上做（#15 的版本号 PR 先合，再推标签）。
- 用户可见断言双通道观测：群卡片截图（真人看到的），对照机器人日志或平台回读。
- 证据只认仓库与 GitHub 留痕。真实数据产物只落服务器私有目录，Issue 只写计数、比例与指纹。
- **产品负责人真人验证块只放两处**：
  - **前置块**（实施最前，一次给齐）：飞书事件订阅保存（#8）；#9 的三项输入；Codex 云端审核接入本仓（#14）；ops 请求若需本人操作。
  - **收口块**（Trace 最后，一次排完）：群里 @千树Bot 发样例（#8 / #2）；发一封测试申请邮件（#9）；通知审批人、配置人后执行 X5（#11）。
  - 每块先由守望者出就绪自检，一次一条指令。

## 5. 成本预算

- **CI 计划**：
  - 本地门禁：实施卡只跑受影响测试；冻结候选跑一次全量。

  - 同机多 Trace 的完整门禁：本仓同一时刻只 1 个 PR 跑全量。

## 6. 主线声明

- **主线**：#4 骨架 → #5 解析（首提交定政策草稿）→ #7 演练 → #10 比对 → 整合卡 → 收口块（#8 群里真跑 + #11 测试单）。

  - 任何派发前先问「不做它主线是否受阻」。
  - 新发现默认登记不立项。
- **`execution_adapter`**：`claude_tmux_named_session`，tmux session `TZ-server`，编排窗口 `qianshu-010`。
  - 守望者 = 常驻项目守望者，会话 `qianshu-28`，窗口 `qianshu`，不归编排者管。
  - 台账 Issue：待首次拉起时新建，由守望者新建后登记到 #12 评论。
  - 编排者有疑问一律发会话消息给守望者，并在 #12 留待裁评论，继续做不依赖它的部分；不问产品负责人。
- **值守机制**：编排者每次派发自挂 `tk-wait`（只认自己的目标、硬超时必填）；Codex 进程按 PID 与报告文件判活。台账文件 `~/.local/share/trace-kit/qianshu/12/ledger.jsonl`，不入库。守望者的事件型与定时型机制由其自行登记。
- **上次复盘建议采用的官方功能**：本仓首个 Trace，无上次复盘。外部路径检查排进任务表 S-0-1。本机 `claude --version` = 2.1.327。
- **收敛线**：内审与外审只处置 P0/P1，以及与本卡完成标准直接相关的 P2。严重级只认无前提的真实损害，如错单、越权、泄露、误写明道云。范围外发现登记不立项；同区打转两轮的出口是「补证据」。
- **合并闸门**：
  - 仓库规则集 `main-required-ci`：必过 `qianshu-checks`、须含最新 main、禁强推与删除。
  - 加本合同：内审结论已处置；第二层外审已处置；云端审核启用后，在最终 head 上 Completed 并逐条处置。
