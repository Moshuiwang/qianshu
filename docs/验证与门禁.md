# 验证与门禁

## 证据等级

| 等级 | 口径 | 判定依据 |
| --- | --- | --- |
| L1 | 已分析 | 已核对需求、当前行为或相关资料，留下分析结论及依据 |
| L2 | 已改代码 | 交付物已修改，能定位实际代码或文档差异 |
| L3 | 本地测试通过 | 在本地运行目标测试并通过，记录命令、范围和输出 |
| L4 | CI 通过 | 候选提交的 CI 检查通过，记录提交、运行链接和实际门禁档位 |
| L5 | 已部署 | 目标环境已部署指定版本，能回读实际生效的版本 |
| L6 | 真实旅程验证 | 在约定环境和版本实际走完用户或系统的真实路径，核对可观察结果 |
| L7 | 回源确认 | 回到权威来源独立回读实际记录或状态，与旅程产出及验收判据核对一致 |

PR 写明实际证据等级和证据指针。Trace 的 `验收.md` 按验收项记录目标等级、实际等级和证据指针。依据实际运行范围定级，判据数值取自程序输出或平台回读。使用模拟边界的结果按实际测试范围记；未运行的验证、证据缺口与批准的降级理由一并记录。对外证据按[协作约定](协作约定.md#提交与披露)做最小披露。

## 门禁档位

| 档位 | 适用范围 | `qianshu-checks` 执行内容 |
| --- | --- | --- |
| 文档档 | 改动全部在 `docs/`、`README.md`、`CHANGELOG.md`、`AGENTS.md`、`CLAUDE.md` 或 PR 模板 | 判定改动范围，跳过依赖安装和代码测试 |
| 完整档 | 改动包含上述范围外的文件，或手动运行无 PR 基线的检查 | 有 `pyproject.toml` 时安装锁定的工具和 uv 托管的 Python 3.12.13，打印 `python -VV` 后运行测试。缺少 `pyproject.toml` 时记录暂无代码检查 |

PR 证据写明检查实际覆盖的范围。Trace 批次的本机门禁、审查和验收条件以当期合同为准。CI 定义见[检查工作流](../.github/workflows/checks.yml)，合并规则见[协作约定](协作约定.md#pr-规则)。

## Python 版本与本机快检

本机、CI 和后续生产环境统一使用 `.python-version` 固定的 uv 托管 Python 3.12.13。CI 和本机快检都显式读取该版本，并以 `--managed-python` 禁止回退到系统 Python。在仓库根目录运行：

```sh
uv python install "$(cat .python-version)"
uv run --frozen --python "$(cat .python-version)" --managed-python python -VV
uv run --frozen --python "$(cat .python-version)" --managed-python python -m pytest -q
```

补丁版本升级按「换版本先评估」处理。运行环境变化可能改变标准库邮件解析等行为，须先评估影响并验证相关测试，再更新版本。
