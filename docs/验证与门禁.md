# 验证与门禁

## 证据等级

| 等级 | 口径 | 判定依据 |
| --- | --- | --- |
| L1 | 已分析 | 已核对需求、当前行为或相关资料，留下分析结论及依据 |
| L2 | 已改代码 | 交付物已修改，能定位实际代码或文档差异 |
| L3 | 本地测试通过 | 在本地运行目标测试并通过，记录命令、范围和输出 |
| L4 | CI 通过 | 候选提交的 CI 检查通过，记录提交、运行链接和实际门禁档位 |
| L5 | 已部署 | 目标环境已部署指定版本，能回读实际生效的版本 |
| L6 | 真实旅程验证 | 在约定环境和版本实际走完用户或系统的真实路径，核对可观察结果 |
| L7 | 回源确认 | 回到权威来源独立回读实际记录或状态，与旅程产出及验收判据核对一致 |

PR 写明实际证据等级和证据指针。Trace 的 `验收.md` 按验收项记录目标等级、实际等级和证据指针。依据实际运行范围定级，判据数值取自程序输出或平台回读。使用模拟边界的结果按实际测试范围记；未运行的验证、证据缺口与批准的降级理由一并记录。对外证据按[协作约定](协作约定.md#提交与披露)做最小披露。

## 门禁档位

| 档位 | 适用范围 | `qianshu-checks` 执行内容 |
| --- | --- | --- |
| 文档档 | 改动全部在 `docs/`、`README.md`、`CHANGELOG.md`、`AGENTS.md`、`CLAUDE.md` 或 PR 模板 | 判定改动范围，跳过依赖安装和代码测试 |
| 完整档 | 改动包含上述范围外的文件，或手动运行无 PR 基线的检查 | 有 `pyproject.toml` 时安装锁定的工具和 uv 托管的 Python 3.12.13，打印 `python -VV` 后运行测试。缺少 `pyproject.toml` 时记录暂无代码检查 |

PR 证据写明检查实际覆盖的范围。Trace 批次的本机门禁、审查和验收条件以当期合同为准。CI 定义见[检查工作流](../.github/workflows/checks.yml)，合并规则见[协作约定](协作约定.md#pr-规则)。

## Python 版本与本机快检

本机、CI 和后续生产环境统一使用 `.python-version` 固定的 uv 托管 Python 3.12.13。CI 和本机快检都显式读取该版本，并以 `--managed-python` 禁止回退到系统 Python。在仓库根目录运行：

```sh
uv python install "$(cat .python-version)"
uv run --frozen --python "$(cat .python-version)" --managed-python python -VV
uv run --frozen --python "$(cat .python-version)" --managed-python python -m pytest -q
```

补丁版本升级按「换版本先评估」处理。运行环境变化可能改变标准库邮件解析等行为，须先评估影响并验证相关测试，再更新版本。

## 本地解析回归考题集

0.2.0 基线、终验和修复后重跑使用同一份冻结考题。样例默认按政策类型和优惠类型分层抽取 150 条，`plan --all` 可生成全量审定计划。实际调用由编排者按 Trace #76 的 X2 授权执行。配置沿用现有模型接口，由调用方预先提供模型配置环境变量。日常测试使用合成资料与假模型。

在仓库根目录运行以下命令。语料根下保留 `policy-corpus/` 和 `wiki-corpus/` 的归档结构。`.private` 由当前用户所有且权限为 0700，须被 Git 忽略。每次在当前 Git 工作树内使用新的输出目录。

```sh
.venv/bin/python -m qianshu.regression plan \
  --corpus .private --size 150 --out .private/exam-plan
# 按 exam-plan/plan.json 的层内顺序完成独立人工审定
.venv/bin/python -m qianshu.regression freeze \
  --corpus .private --plan .private/exam-plan/plan.json \
  --reviews .private/exam-review.json --companies .private/companies.tsv \
  --out .private/exam-v1
freeze_sha=$(.venv/bin/python -m qianshu.regression verify --frozen .private/exam-v1 --sources)
.venv/bin/python -m qianshu.regression run \
  --frozen .private/exam-v1 --expect-sha256 "$freeze_sha" --live --out .private/exam-baseline
```

`verify` 读取冻结时的抽样计划，逐层核对类别、配额和候选数。加 `--sources` 时同时核验其余来源文件的指纹。加载冻结考题时，分层配额和纳入数合计须分别等于目标配额和样例总数。

审定文件是私有 JSON，顶层有 `schema: 1`、`reviewer_role`、`reviews` 和按需填写的 `mapping`。以计划中的 `row_id` 为 `reviews` 的键，每条记录填写以下内容。

- 对无法可靠配对的候选填写 `exclude`。允许的原因是 `not_applicable`（不适用）、`gold_missing`（配置缺失）、`historical_rule`（历史规则差异）、`insufficient_evidence`（证据不足）、`source_anomaly`（源数据异常）。抽样时按计划顺序用同层候补补足，全量模式逐条审定。
- 某层纳入数不足配额时，须审定该层全部候选才能按实际纳入数冻结，冻结清单和公开报告逐层记录配额、实际纳入数与缺口。
- 对纳入的候选填写 `span: [start, end]`，按归档 `plain_text` 的 Unicode 字符从零计数，含起点、不含终点。段落覆盖政策标题。无标题的单条原稿从 0 开始。用 `basis` 记录原稿版本、段落归属、配置的核对依据和复核裁决。补充素材可在 `materials` 中登记相对语料根的文件路径，冻结时记录文件指纹。
- `fields` 为每个核心字段标记 `true` 或一个上述排除原因。核心字段包括 `policy_name`、`company`、`policy_type`、`benefit_type`、`start_date`、`end_date`、`recharge_days`、`gift_days`、`maintain_mutual_exclusion_group`、`trigger_once`、`cancel_on_downgrade`、`repeat_bonus`、`effective_multiplier`、`user_tags`、`packages`、`user_scope`。结合表格、图片及附件核对证据，涉及归档正文无法支持的字段，记录排除原因。
- 含枚举、公司或关联子表的可比字段需要可核对的字段映射。`mapping.options` 按字段提供私有选项 ID 到规范名称的映射，已有字段字典映射可直接使用。`mapping.company_names` 记录公司关联记录 ID 到规范显示名的对应。关联记录 ID 在比较、建立映射和冻结前统一转小写。主记录通过 `sid`、`rowId`、`rowid` 或字符串 ID 数组提供 ID 时，须和关联明细的 `rowId` 一致，否则停止冻结并复核。归一后的公司 ID 对应多个不同公司名时，相关样例的公司字段判为不确定，以 `source_anomaly` 记录，整批继续冻结。`mapping.relation_columns` 用 `user_tags`、`current_package`、`gift_package` 指定关联记录列键。节目包度量覆盖当前包和赠送包名称，价格计划与结束去向超出此度量范围。
- 在顶层 `documents` 按原稿 token 登记 `package_style`。按整篇原稿审定，取值为 `tier_only`（只写档位）、`name_only`（只写包名）、`both`（两类并写）或 `neither_recognized`（两类都没认出）。同篇原稿含多条入选政策时计一篇。旧版冻结资料中缺少写法登记的原稿单列为「未登记写法」。
- 批次原稿可在 `documents` 中登记 `other_spans`（已核对、未参与评分的政策段落）。已核对文档中所有政策段落时设置 `complete: true`，用于区分额外草稿和归属未核实的草稿。

冻结后保存 `manifest.json` 指纹用于复跑。相同输入生成相同的样例 ID、分母和内容指纹。创建时间保存在 `audit.json`。每篇批次原稿完整送入解析入口一次，按原文段落对齐政策。草稿越出审定段落时，须有可唯一定位的段内摘录确认归属。草稿段落内重复出现的字段摘录须全部落在同一审定段落，跨段或仅见于段外时计为歧义。字段分母在冻结时确定，解析失败、结果缺失或判为不确定仍计入相应分母。复跑出现新增字段时，按已确定、不确定、缺失和未唯一对齐报数量。枚举、日期、天数和名称严格比较，节目包按当前包和赠送包组成的行集合比较，重复行计为异常。审批链接与附件只报可用性。用户范围的一致率基于全文相等。

仅将 `public-report.md` 中的计数、比例和指纹用于对外汇报。`public-report.json` 提供按字段和分组的交叉计数，国家用冻结后稳定的分组编号表示。`mismatches.json` 含人工值、解析草稿、证据和国家分组映射，随冻结资料留在私有目录。模型原始回复仅在内存中处理。复跑时核对相同冻结指纹，并以 JSON 中的整数分子和分母计算一致率变化。中断后用新的输出目录重跑。

## 0.3.0 回归量尺

同一份模型回复用两把量尺出数，公开报告并列。新量尺先做业务配对，再按冻结分母逐字段评分，以「可比字段全对率」等指标判定门槛。旧量尺继续报告唯一对齐、未对齐和歧义，用于诊断。配对、评分类别与门槛见 [解析协议第 5 节](解析协议.md#5-回归量尺)。

放行运行按指定次数报告均值和最小–最大值，用于判断提升和不劣。单次诊断运行用于找问题。同协议且只改程序时，对已存回复离线重放。各阶段的运行次数、留集范围和波动计法见 [解析协议第 6 节](解析协议.md#6-留集与波动计法)。
