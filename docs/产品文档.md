# 产品文档：运营政策配置机器人

- **版本**：v0.1 草稿
- **更新日期**：2026-11-18
- **需求来源**：[会议记录 2026-11-18](会议记录/2026-11-18-运营政策配置流程.md)

---

## 1. 背景

各国运营每月通过邮件提交 30～50 条优惠政策申请，大促时更多（圣诞一次 100 条），全部由配置负责人在明道云中手工录入。这项工作耗时，有时导致政策不能及时上线。

## 2. 目标

| 目标 | 衡量方式 |
|---|---|
| 替代人工录入 | 标准申请邮件由机器人自动建单，人工只处理异常 |
| 上线更及时 | 确认邮件审批同意后，几分钟内完成标准申请的建单 |
| 节省人力 | 每月节省 ≥ 20 小时 |
| 不降低准确率 | 明道云政策审批时的退回率不高于人工录入时 |

## 5. 使用流程

### 5.1 主体流程

使用 CRM 标签时，申请人须在建单前完成标签申请（D8）。公开活动的申请邮件须附公开政策审批完成的 PDF，机器人核对附件的功能列入后续版本（第 7 节）。

```
各国运营发邮件提交政策申请
   ↓
邮件审批人回复申请邮件
   ↓
机器人在「已发送」中核验回复及其关联申请，按 6.1 提取本次新增的回复供 AI 判断。判为「同意」后读取申请并整理待填字段
   ↓
机器人新建飞书存档文档，并在知识库汇总页登记链接（D14）
   ↓
机器人逐条校验，在指定飞书群发拟建单审批卡片，任一群成员可点击「同意」
   ↓
机器人核验有效同意后，在明道云为卡片绑定的政策建单，状态为「新建」
   ↓
人工在明道云提交申请，进入「待审批」
   ↓
政策审批人在明道云手动审批，通过后进入「待配置」
   ↓
政策配置人把政策配置到 iBoss
```

## 6. 功能需求

### 6.1 收件与邮件审批

| 编号 | 需求 | 优先级 |
|---|---|---|
| F1.1 | 自动监控配置指定的网易企业邮箱，识别政策申请邮件。确认邮件审批同意后，启动字段解析、存档与建单流程（D6、D16） | P0 |
| F1.2 | 飞书群保留拟建单卡片审批、汇报、追问和纠错功能（6.5、6.6）。「群申请直达建单」路线已停止（[#38 方向变更](https://github.com/Moshuiwang/qianshu/issues/38#issuecomment-7038089568)）。群内申请正文解析仅限 0.1.0 概念验证期按 9.2 执行的 X4 演练。正式申请仍走邮件入口并按 D16 核验邮件审批 | P0 |
| F1.3 | 同一封邮件不重复处理。需要重跑时，在群里明确说「重新处理」，仍须满足邮件审批和群卡片审批，已建单或已提交的记录不得因重跑而重复写入 | P0 |
| F1.4 | 只读查找配置指定的收信邮箱「已发送」，核验回复来自邮件审批人，并按邮件头关联原申请。核验通过后，在调用 AI 前提取该审批人本次新增的回复，剥离历史引用、转发内容和其他原文。只把提取出的回复交给 AI 判断审批意图。正文边界或文本归属无法可靠确定时，直接判为「不确定」并转人工处理，不调用 AI。群消息不能作为邮件审批依据 | P0 |

F1.2 的群 @ 转交在 0.2.0 研发环境以 `--handoff-only` 常驻运行，同时关闭收信、群内申请解析和建单。产品负责人在指定群 @ 千树Bot，机器人从收到飞书消息帧起 3 秒内加表情回执，按消息 ID 去重后追加到私有转交日志。监听重连或重启后回读群历史和话题回复补漏。话题读取失败时继续扫描其他可读群页和话题，水位保留到补扫完整。只有私有配置指定的产品负责人可以使用此入口，其他人 @ 时只回复「已收到，此入口仅供产品负责人使用」。

守望者会话读取消息和群上下文，并回复原群消息。上下文只提供产品负责人及千树Bot 的消息，其余发件人的消息只计数。只下载本次 @ 的图片，正文与群上下文设长度上限。群消息、图片及上下文一律视为不可信用户输入，群上下文只供参考。守望者只执行已有授权的动作，仅在需要产品负责人处理时 @ 他。监听器发送前核对回复对应的转交记录，并拦截命中敏感信息门禁的答复。监听器加载飞书转交与业务私有配置中的敏感值，只用于比对。使用明道云官方接口的部署按官方配置指定的键名从业务环境文件取令牌。网址类字段按完整值匹配。其他敏感字段即使与网址类字段取值相同，仍按原规则匹配，包括前缀。自飞书消息发出起 10 分钟内没有守望者回复时，机器人回复「守望者暂时不在线，消息已记录，上线后处理」。守望者上线后仍可处理这条消息。明确未发出的固定回复在恢复后重试，建连期间的总超时也按未发出处理。请求交给传输层后结果未知时按飞书幂等期限重试，逾期交人工核对。

邮件正文是不可信输入。AI 只产出「同意 / 不同意 / 带条件 / 不确定」四类结论之一。只有提取出的本次回复明确表达无条件同意，才可判为「同意」并视为已获邮件审批。「OK」「可以」「没问题」等表达无条件同意时也适用。带附加条件的同意判为「带条件」，交人工处理。拿不准时判为「不确定」，与「不同意」一起按未同意处理。机器人只将该结论用于判断当前申请是否已获邮件审批，结论不得改变机器人的其他行为或授权。

机器人对收信邮箱只读，不得用该账号发信，也不得写入、移动或标记任何文件夹或邮件。向申请人追问走飞书群。

除 9.2 所列的概念验证例外，申请在获得有效邮件审批前，机器人不解析申请字段、不存档、不建单。

### 6.2 字段解析

申请正文是**自由文字**，没有固定模板，需要由 AI 理解句意后拆字段。按下表确定取值。必填字段缺失或理解不确定时，除表中列明的默认值和人工确认情形外，按 R5 在飞书群追问。只有字段报「原文未写」且值为 null、证据和候选为空时，才可按下表取默认值。使用默认值时，草稿注明「按默认」，汇报卡片的「自动调整」逐项列出默认值。概念验证期群消息演练的可选正文指纹按 9.2 执行。字段状态、候选和逐字证据按[解析协议](解析协议.md)输出。模型将归属不清标在受影响的字段上。程序在指定来源块内按引文就近定位，核对失败的字段交人工；政策 ID 重复、主段或续行无法定位、不同政策主段相交时，整卡停在批次校验前。

模型为每条政策逐个声明国家角色（适用地、比较或背景、排除对象）。程序在指定输入块内唯一定位国家支持引文与各角色短引文，换算到原始来源；支持引文与背景或排除引文共享任一字符即有冲突。角色引文按受信表匹配完整国名及别名，长名内的短名只在另有独立出现时计入。适用地须唯一查表且与国家确定值一致，同一适用地不得同时被排除。缺角色或证据、引文无法唯一定位、角色矛盾时，本条国家、公司交人工，依赖国家代码的公开政策拼名及依赖公司的节目包查表也随之转人工。若仅因国家角色待核而无法展示拼名建议，其候选名仍参与同批逐字查重。模型所报带条件等状态保留。

模型判断日期用途和适用对象。首个政策标题之前的前言仅作为起止日期的依据。前言中按国家或公司限定的日期只适用于匹配的政策，归属不清时判为不确定。「申请时间周期」等标明申请周期的区间可在前言或批次共享段作为起止日期依据，无独立政策标题的单条申请可用正文中的申请周期。带作废、停用、罚停等限定词的区间不得作为政策起止日期。

从邮件中识别以下字段，一条政策对应一条单据。字段名按明道云表单实际名称（10.4）。仅填写该优惠类型及金额方式下表单显示且需手工填写的字段，页面自动带出的字段按 10.3 处理。

| 明道云字段 | 解析与填写规则 |
|---|---|
| 优惠政策名称 | **公开政策**的用户标签须有原文明示为空的证据。申请明确给名且有逐字引文时照用，卡片标「申请原文」。核实原文未写名称时，用查表所得国家代码、本条有证据的活动或优惠短名和 R1 后实际生效开始日，按「国家代码_短名_YYYYMMDD」拼出，卡片标「按格式拼出，待同意」，经产品负责人在群卡片上同意后才可建单。类型或名称待定、询问、带条件、冲突、缺证据，或无法确定拼接所需的短名、国家代码或生效开始日时，转人工。**定向政策**沿用本条唯一且确定的用户标签名。标签缺失、有多个、不确定或原文名称与标签冲突时，转人工。两类名称均须全局唯一，长度暂按 50 字符（官方上限待核）。草稿逐字核对同批名称及调用方提供的已知名称；群入口仅查同批；重名或超长转人工，现有明道云建单查重照常执行 |
| 是否需要维护互斥组 | 按 R7 填写。0.1.0 概念验证期明确要求不维护时标为不确定，交人工确认 |
| 公司 | 按国家查私有公司对照表，每条政策对应唯一一家公司。优先匹配本条政策或适用批次共享说明中该国配置的关键词。原文给出确定的公司主体或线索、但查表无关键词命中时，视为与该国默认公司冲突，判需确认；原文完全没有公司线索时，才用该国默认公司。国家无法识别、对照表缺失或无法据表确定公司时，判为不确定（R10） |
| 政策类型 | 用户标签确定且非空时填「定向政策」，确定为空时填「公开政策」。用户标签或段落边界不确定时，政策类型也标为不确定。原文或模型给出的类型与标签判定冲突时，标为不确定并列出两种候选。确定时在卡片的「自动调整」中注明「政策类型按用户标签判定」（G168、R8） |

| 指定金额方式、充值金额、关联资费、资费倍数 | 适用于特价优惠。固定实付金额选「自定义」并填写正文金额。正文明确按节目包资费计算时选「节目包资费」，按生效开始日期查验基本包、价格计划、资费单元的唯一有效版本，再以资费乘正文倍数并向下取整。正文另有明确金额时核对计算结果。固定实付金额缺失、资费依据缺失或无唯一有效项、金额冲突、有多种解释时按 R5 追问。资费倍数用于计算金额，生效倍数用于判断达标，两者分别记录 |
| 优惠后是否升包 | 适用于升级权益和特价优惠，按正文写明的到期去向填写。明确恢复原包时填「恢复原包」；明确到期转入或留在指定包时填「指定节目包」并核验目标包。正文未写到期去向时默认填「恢复原包」，在汇报卡片的「自动调整」中注明。到期去向有歧义时按 R5 追问，活动期间获得的更高档权益只用于判定活动期间的权益 |
| 获得优惠后不允许换包 | 适用于升级权益和特价优惠。正文明确允许换包时填「否」，明确禁止时填「是」；未写时默认填「是」，在汇报卡片的「自动调整」中注明。按优惠期间的换包条款单独判断，表述不清时按 R5 追问 |
| 仅首充日享受 | 仅适用于特价优惠。只有正文明确要求首次充值当天才填「是」，未写时留空，表述不清时按 R5 追问。与「是否只触发一次」分别判断 |
| 多买多送 | 正文明确允许时填「是」，明确不允许时填「否」，未写时默认填「是」 |
| 生效倍数 | 正文未写时默认填 1，并在汇报卡片的「自动调整」中注明「生效倍数按默认填 1」。明确写 1 时照填；明确为其他倍数或表述不清时，标为不确定并转人工确认后再建单 |
| 用户标签 | 识别标签名，可多选。所用 CRM 标签须已完成申请，本版以明道云报错为准（R2、D8）。建单时按 R2 经官方接口在私有配置指定的标签表里查找，恰好 1 条才用。影子标签类活动只能选一个（R3） |
| 节目包（子表） | 有独立标题且本条明确的当前包按原顺序逐行填写。赠送时长取当前基本包，升级权益和特价优惠取本行明确的活动期受赠基本包，各自查其同步附属包。重复、冲突、归属不清、查表失败或任一行缺失时，整项待核。只写档位时按确定的公司、平台及同类数字级别列只读候选，单一候选也须人工核对 |
| 用户范围（「适用条件」页签） | 必填自由文本，可按申请描述概括活动对象，如「休眠用户召回」。段落边界确定、取值非空，且模型引用本条政策或适用的批次共享段、至少一条摘录经程序逐字核实时，判为确定。取值为空、无有效摘录或段落边界不确定时，判为不确定（G187、R9） |
| 任务审批链接（「审批件」页签） | 解析时沿用原文中符合条件的本批存档链接。原文没有此类链接时草稿留空，卡片显示「建单时填写」，不阻挡解析校验。建单时须填有效网址。0.1.0 的 X5 测试单沿用模板记录链接，正式单使用本批存档文档链接（G168、6.7、D14、R9） |
| 审批件附件 | 段落边界确定时默认留空，草稿记为确定的空列表，卡片的「自动调整」中注明「审批件按默认留空」。段落边界不确定时标为不确定（G168） |

| 适用情形 | 草稿及离线组装字段 |
| --- | --- |
| 赠送时长 | 充值天数、赠送天数 |
| 升级权益 | 充值天数、赠送天数、优惠后是否升包、获得优惠后不允许换包。到期选「指定节目包」时查验并填写目标包 |
| 特价优惠 | 可看天数、指定金额方式、充值金额、优惠后是否升包、获得优惠后不允许换包。按节目包资费时填关联资费和资费倍数。到期选「指定节目包」时查验并填写目标包。仅在明确适用时填「仅首充日享受」 |

优惠字段的默认值须有值为空、无证据且无候选的「原文未写」声明。模型按交易条件和权益区分「充一个月送一个月」和「充一个月的钱看两个月」，拿不准时按 R5 追问，并把有证据的候选列在卡片上。优惠字段的适用口径见 [DG1 裁定](https://github.com/Moshuiwang/qianshu/issues/69#issuecomment-7061172101)。

资费和到期目标包使用私有对照表 `.private/benefit-catalog.json`。表内 `tariffs` 数组逐项记录 `base_package`、`price_plan`、`unit`、`version`、`amount`、`valid_from`，可选 `valid_until`。日期使用 YYYY-MM-DD，起止日均含当天。`package_names` 数组记录可作为到期目标的节目包名称。查不到、查到多条或表不可读时，相关字段交人工确认。

销售品明细默认读取私有目录中的 `package-levels.csv`（UTF-8，可带 BOM）。按已核公司的内部编号和显示名定位管理主体，按政策起始日与运行日中较晚的一天核对在售状态和起止日期。离线解析可注入同一份冻结销售品快照；仅有汇总计数时交人工核对。

#### 编辑公司对照表（0.2.0）

- 将表格保存在私有配置目录，不进仓库。默认路径为启动工作目录下的 `.private/companies.tsv`，也可通过 `--companies-file` 指定私有目录中的 CSV 或 TSV。仓库提供[格式说明](../rules/parse-rules.md#trace-12--sc6b-公司默认值与关键词)和[一行合成示例](../rules/companies.txt)。
- 用表格软件打开并按需编辑，以 UTF-8 CSV 或 TSV 保存。首行依次为「国家」「关键词」「公司内部编号」「公司显示名」。国家填写国家名规则中的标准名称。关键词留空表示该国默认公司，每国至多一行。内部编号按文本保存以保留前导零，供人工核对。公司显示名填写明道云中的完整显示名。
- 可先保存到同一私有目录的临时文件，确认格式后替换原文件。下一封申请会读取更新后的表格，无须重启。同一份申请内各条政策使用同一次加载结果。默认校验四列表头。需要回退时，启动服务或运行独立解析命令时显式加上 `--legacy-companies`，按旧的无表头两列或三列 TSV 读取，顺序为国家、显示名、可选关键词。
- 回归工具读取冻结时保存的公司表内容，使用相同校验规则。冻结产物使用旧格式时，在回归工具的 `run` 命令上显式加 `--legacy-companies`。
- 修改人按规则层约定在飞书群说明改了什么、依据谁的哪句话。修改记录在私有目录只追加，保留历史记录以便回滚。
- 旧主名「刚果金」「刚果布」分别归一为「刚果（金）」「刚果（布）」，归一后按同一国家校验。国家未收录的行会跳过，其他有效行照常生效。表头或列数错误、必填列为空、同一国家有两行默认公司或有冲突关键词时，公司一律判为不确定，其余字段照常解析。行级日志的格式统一为「公司对照表第 N 行」。

### 6.3 校验规则

| 编号 | 规则 | 不满足时 |
|---|---|---|
| R1 | 生效开始日期不早于今天 | 自动顺延，并在汇报中说明 |
| R2 | CRM 标签须在建单前已完成申请。X5 按标签名查询私有配置指定的标签表，须恰好一条同名记录；其他版本以明道云表单或保存时报错为准（D8） | 未完成、标签不确定、查询结果为零条或多条、或明道云报错时，停止建单并请申请人核实 |
| R3 | 影子标签类活动（需用户点确认）只能选一个标签 | 不建单，追问申请人 |
| R4 | 同一批政策中两条用户数相同，提示可能选重了标签 | 建单，汇报中标黄提醒 |
| R5 | 必填字段有缺失或理解不确定 | 不建单，追问申请人 |
| R6 | 每行按确定的主体，在私有销售品明细中查到唯一有效的基本包与受赠基本包的同级同步附属包（父项及精确名称 `_copy` 一致） | 任一行无法查实则停止建单，汇报原因 |
| R7 | 赠送时长、升级权益和特价优惠均适用。申请正文明确为「否」才填「否」（选「否」会跳过配置直接生效），明确为「是」时填「是」。0.1.0 概念验证期对明确为「否」的申请按 6.2 交人工确认 | 正文没写且归属明确时才默认填「是」，并在汇报卡片的「自动调整」中注明「互斥组按默认填是」。表述或归属不清时按 R5 追问 |
| R8 | 政策类型按 6.2 根据用户标签判定。定向政策必须有用户标签，公开政策的用户标签为空。选用标签时，政策结束日期不晚于标签最晚结束日期 | 不建单，追问申请人 |
| R9 | 解析校验须确认「用户范围」，建单还须提供有效的「任务审批链接」（网址） | 用户范围缺失时追问申请人。缺少有效任务审批链接时不建单，按 6.2 补齐链接 |
| R10 | 按 6.2 识别国家并查私有对照表。原文给出确定的公司主体或线索、但查表无关键词命中时，视为与该国默认公司冲突，判需确认；原文完全没有公司线索时，才用该国默认公司。多个关键词命中或关键词与明确写明的公司主体冲突时，判为不确定。X5 从已登记的同国家模板可读关联中按公司显示名选取唯一记录，回读时核对公司显示名与关联记录 ID | 解析无法确定时不建单，按 R5 追问。组装无法确认时停止建单并交人工核对。公司回读无法确认时保留已建记录，交人工核对 |

G168 的字段口径依据近期「新建」视图的 31 条记录。审批件附件均为空，有用户标签的 27 条均为定向政策，无用户标签的 4 条均为公开政策。

**原则：拿不准就不建。** 宁可多追问一次，也不建一条看起来正确、实际猜错了的单据，因为这类错误在审批时很难发现。

### 6.5 群内审批与汇报

每封获邮件审批的申请完成建单预检后，机器人在指定飞书群发拟建单审批卡片。X5 按 9.2 预检后也在该群发卡片，列出一条拟建测试单的政策名称、起止日期、充值与赠送天数、用户标签及节目包。审批卡片及建单结果汇报包含：

- 邮件来源：国家、申请人、邮件标题
- 审批卡片列出拟建条目；建单结果汇报列出已建条数及可用的明道云链接
- 自动调整，按 6.2 和 R7 列出默认值、时长换算和待确认项，以及日期顺延等变更，例如「生效日期已由 2031-04-08 顺延至 2031-04-12」（合成日期）
- 未建单：哪几条、原因、需要谁补什么
- 提醒项：如 R4 疑似重复标签
- 拟建单卡片提供「同意 / 驳回」按钮。两种操作仅适用于该卡片绑定的建单登记

在同一指定汇报群的申请详情卡上，「处理状态」后、各政策草稿前可展示「没用上的原文段落」，逐段列原文和一句理由，仅供阅读。字段旁列逐字引文，可附简短说明。卡末「申请原文」附本次解析收到的正文，包括零草稿或解析失败时；所有展示文本先脱敏再分页。非空材料解析成功但零草稿时显示「未提取到可办理的政策，请核对原文」。邮件汇总只列固定状态和计数，不带原文。

机器人只接受经飞书 SDK 认证的本应用长连接上的 `card.action.trigger` 回调，校验回调中的指定汇报群和卡片消息标识，按回调去重并在 3 秒内应答。同意或驳回均须从可信回调取得点击人身份，并核实其点击时是指定群的当前成员。身份或成员资格无法确认即拒绝操作。在私有台账记录点击人和时间。

常规审批卡片在发出日后的第二个 UTC 零点到期。发出日后的第一个 UTC 零点，若尚无有效点击，机器人在群里 @ 配置负责人提醒一次，并继续接受合规回调。到期时关闭审批并公告，尚未发出建单请求的条目按「未建单」交人工处理。0.1.0 的 X5 卡片以当次验收窗口为有效期。回调校验和建单请求发送共用同一截止时间，达到截止时间时拒绝回调并禁止发出建单请求。

群卡片有效驳回时，机器人关闭审批，在群里公告未建单条目及原因，并 @ 配置负责人处理。明道云审批人或配置人退回时，机器人在群里公告涉及的条目及原因，并 @ 配置负责人，由其人工修改、重新提交或作废。需要申请人补充时，机器人在群里列出要补的内容。测试单清理按 D15 执行。

#### 正式单与测试单共用的建单门禁

1. 卡片消息标识、一次性审批标识和拟建单登记须绑定。登记绑定配置、草稿及登录态摘要；缺失或不匹配即拒绝。
2. 唯一建单入口须核验绑定卡片上的有效同意。发出前检查当前应用连接、验收窗口、登录会话，并用官方接口确认无同名记录。
3. 建单请求以实际交给传输层发送且本地无法撤销为界。关闭审批和发出请求共用同步机制。在临界区内先持久记录一次发送尝试，重新核验连接及同一截止时间，再发出请求。曾发出或无法证明未发出时，禁止再次认领相同 Trace 的建单资格。
4. 驳回、到期、断线或窗口关闭时须持久关闭审批，并公告尚未发出请求的条目「未建单」。重连或重新登录后作废旧审批任务及待发请求。审批关闭后收到的点击不得授予建单资格；关闭先于认领时认领失败，认领后、发出前关闭则认领作废。
5. 建单结果未知时冻结清理，只按名称回读并人工对账。建单获确认后以官方接口回读逐字段比对；提交、撤回由人工在明道云操作。仅符合 D15 的测试单可由机器人删除。

测试单也须通过全部共用门禁，并符合 D15 的建单登记要求。0.1.0 的 X5 还须核验 S-5-2 当次授权已登记。

### 6.7 申请存档：机器人自建文档 + 知识库汇总页登记（D14）

会议中的归档目录位于运营团队的飞书知识库（会后核实，2026-11-18）。人工按国家、年份、操作日期归类申请并登记政策明细，存档页的链接就是明道云必填字段「任务审批链接」的值。

**机器人的做法（D14，2026-11-18）**：知识库与千树Bot 不属于同一组织，机器人无法成为知识库成员，不能在知识库目录下新建页面（只能编辑已有页面）。因此改为：

| 项 | 规则 |
|---|---|
| 存档文档 | 每批申请在邮件审批通过并整理字段后，机器人在**自己的飞书云空间**新建一份文档，写入申请明细原文：活动周期、每个标签的用户数、政策内容、使用场景、标签名称 |
| 分享范围 | 「互联网上获得链接的人可阅读」：拿到链接的任何人都能看，链接被转发到公司外也能看 |
| 汇总页登记 | 在知识库中按政策类型选择定向活动汇总页或公开活动汇总页，在对应页末尾追加一行，写上该文档的链接。两页由产品负责人建好，页面地址只存服务器 `.env` |
| 链接用途 | 该批所有政策的「任务审批链接」填**本批存档文档的链接**（不填汇总页链接） |
| 时刻 | 文档标题与汇总行中的日期、时刻按 UTC（第 8 节） |
| 待定 | 汇总页每行除链接外还写哪些内容（日期、国家、条数等）；一批同时含定向与公开政策时怎么登记 |

人工录入时在知识库的活动分类下按「大区 → 国家 → 年份 → 日期页」归档，日期页标题用 `YYYYMMDD` 格式。机器人存档后，从定向或公开活动汇总页查找历史。

**验证（2026-11-18 16:09 UTC，研发机）**：机器人建测试文档、设链接可读、在定向汇总页追加带链接的测试行，均通过；未登录飞书的浏览器能打开测试文档并看到正文。汇总页上留有一行标「【测试】」的记录。

**存档合成示例**：示例国的 `20300615` 日期页可登记 6 个标签和 6 条对应政策。例如，标签和政策名称均为「示例标签_召回_01」，活动为充 40 天送 20 天。该批每条政策的「任务审批链接」均使用同一份存档文档的链接。

其他发现：明道云已有记录的「任务审批链接」绝大多数是知识库页面，少数是 Jira 工单链接，什么情况下用 Jira 待确认。

可信度：**确认**＝官方文档写明；**推断**＝文档未写，按上下文判断；**待实测**＝需要上线前在测试环境验证。

### 10.1 飞书机器人

| 能力 | 结论 | 可信度 |
|---|---|---|
| 长连接收消息 | 企业自建应用可用；官方 Python SDK `lark-oapi`；服务器只要能出公网，不需要公网 IP 和域名。每条事件需在 3 秒内响应，超时平台会重推，所以收到后先回执、再慢慢处理；可能重复推送，用 `message_id` 去重 | 确认 |
| 海外服务器 | 文档未提地区限制；飞书租户连 `open.feishu.cn`（国际版 Lark 连 `open.larksuite.com`，两者不通用） | 推断 |
| 群里能收到的消息 | 默认只收 @机器人 的消息（权限 `im:message.group_at_msg:readonly`）。收全部群消息需要敏感权限 `im:message.group_msg`，要企业管理员审批 | 确认 |
| 回复机器人卡片但不 @ | 文档未说明；判断只有 @ 权限时收不到 | 推断，待实测 |
| 卡片按钮回调 | 支持，走长连接，事件 `card.action.trigger`，3 秒内响应 | 确认 |
| 核实群成员资格 | 核实卡片点击人的群成员资格（6.5）需要飞书读取群成员的权限。上线前核对应用的授权，并验证其在指定汇报群中能读取成员 | 待实测 |
| 发送人身份 | 每条消息带发送人 `open_id`，可再查通讯录得到姓名，用于记录「谁提出的修改」（D9） | 确认 |

**对设计的影响**：群成员纠正机器人时需要 **@机器人**（例如在卡片下回复并 @），这样不用申请敏感权限。若希望不 @ 也能识别，需要管理员审批「获取群组中所有消息」权限，机器人会因此看到群里所有聊天内容。

### 10.3 明道云：复用现有表单的实现方式（D10）

**原理**：在浏览器里每一次点击（新建记录、填字段、点「提交申请」），背后都是浏览器向明道云发出的一个网络请求。程序可以用同一个账号登录，发出同样的请求，效果与人工操作相同。Linux 服务器没有显示器，但这不影响：程序直接发请求不需要浏览器；需要浏览器的步骤（如登录页有脚本校验）可以用「无界面浏览器」在服务器上运行。

**两种做法，按优先级使用**

| 做法 | 怎么做 | 优点 | 缺点 |
|---|---|---|---|
| 1. 直接发请求（X5 路径） | 复用登录会话发出网页同款建单请求，子表随主记录写入 | 不受页面布局变化影响 | 明道云升级可能改变请求格式 |
| 2. 无界面浏览器模拟点击（早期调研） | 在服务器打开表单做填表演练 | 可观察表单行为 | 页面改版时需调整自动化 |

**代价与风险**（这是不改明道云、不找管理员要付出的成本）

| 风险 | 说明 | 应对 |
|---|---|---|
| 用真人账号操作 | 记录的申请人、操作日志显示为产品负责人账号（D13） | 账号信息及登录态存于服务器私有文件，群内汇报由机器人建单 |
| 登录可能被拦 | 海外服务器首次登录，明道云可能要求验证码或提示异地登录 | 机器人自动登录并保存登录状态，失效时自动重登（F4.4）；仅当要求验证码或新设备确认时，在群里 @ 产品负责人处理（F4.5）。研发机没有显示器，验证码无法靠在服务器上弹出浏览器手动处理，具体处理方式待登录验证（第 9 节第 14 项）后确定 |
| 内部请求会变 | 明道云升级后请求格式可能变化 | 失败时停止并上报；建单结果未知时只回读并人工对账 |
| 平台规则 | 非官方的自动化方式，明道云不提供支持 | 控制频率（每条间隔数秒），不做批量抓取 |

**录制结果（2026-11-18）**：用户授权后，Claude 在已登录的浏览器里新建了一条「【测试】」开头的政策记录并点击了「提交申请」，同时记录了网络请求。字段 ID、选项 ID 等内部标识保存在本机私有文件 `.private/`（不进仓库）。

| 操作 | 录到的请求 | 结论 |
|---|---|---|
| 新建记录 | 一个「新增记录」请求，带 55 个字段 | 人工只填约 17 个字段，其余约 38 个由**页面在浏览器里自动计算带出**：申请人、审批人、配置人、通知人群、公司 ID、iBoss 接口字段一组、同期有效政策列表、标签汇总、节目包价格等 |
| 提交申请 | 一个「启动流程」请求，参数是表 ID、记录 ID 列表、按钮 ID | 很简单；记录 ID 是列表，一次可提交多条；提交后状态从「新建」变为「待审批」 |
| 登录 | 未录（录制会打断当前登录） | 不需要录：研发机上用无界面浏览器填账号密码登录已通过，未触发验证码（2026-11-18） |

**据此调整做法**：

- **X5 通过接口建单**。用官方接口读取私有配置指定的同国家模板。名称、日期、天数、用户范围、用户标签、节目包 6 项按草稿取值。节目包名称逐行与模板一致才整行照抄。公司关联在模板可读的关联行里按显示名精确选出唯一记录。私有建单配置在公司控件下用 `display_name_key` 指定关联行的显示名字段。下一份申请按更新后的公司对照表解析。若表格指定的公司不在模板可读关联中，或查到多条、无法核实显示名，组装停止并交人工核对。模板外公司目前没有已确认可用的只读来源。其余字段按模板和固定值配置取值。草稿的确定值与模板冲突时停止，列明字段并交人工。测试单可照抄模板的任务审批链接，正式单遇到同一情形须停止。
- **通过 6.5 的共用门禁后发送一次网页同款建单请求**。工作流照常触发。官方接口逐字段回读比对，首次实测确认的工作流回填字段可在私有配置中列为跳过比对。公司关联回读核对显示名和所选关联记录 ID，无法确认时保留已建记录，交人工核对。提交、撤回由人工操作。
- **「提交申请」按钮只对申请人本人显示**：申请人字段默认是登录人，所以机器人用谁的账号登录，谁就是这些政策的申请人。

**已调研的官方接口与按钮能力**：按已授权的官方接口做读取和 D15 删除；按钮提交、撤回由人工操作。D10 仍要求保持明道云配置。

### 10.6 明道云审批流程与状态跟踪（2026-11-18 页面观察）

**视图与当时的记录数**：新建 31｜待审批 0｜待配置 0｜配置完成 3047｜生效政策 102。另有两个与 iBoss 有关的视图，创建完成待上架 2 条，操作失败 0 条。

**流程**（明道云状态根据「流程待办 → 抄送」通知还原，建单前按 D7 校验群卡片）：

```
群卡片有效同意 ──机器人建单──▶ 新建 ──人工提交申请──▶ 待审批
待审批 ──政策审批人通过──▶ 待配置
待配置 ──政策配置人在 iBoss 配置──▶ 配置完成 ──▶ 生效政策
待审批 ──政策审批人退回──▶ 新建
待配置 ──政策配置人退回修改──▶ 新建
```

| 通知标题 | 含义 | 合成示例 |
|---|---|---|
| DVB政策审批通过 | 审批人通过，进入待配置 | 「审批政策通过待配置：示例国-赠送时长-充40送20-2030-06-15-000001」 |
| DVB政策退回申请 | 审批人退回，回到新建 | 1 条示例国政策因申请字段需要补充，被审批人退回 |
| DVB政策重新修改 | 审批通过后，配置人退回要求修改 | 「退回政策修改：示例国-赠送时长-充40送20-2030-06-16-000002」 |

每条通知带一个**政策编号**，格式为 `国家-优惠类型-优惠内容-生效日期-流水号`，上表中的编号均为合成示例。

**机器人对审批与配置状态的跟踪**。退回处置按 6.5 执行，其余跟踪建议纳入第一期。

| 跟踪点 | 机器人动作 |
|---|---|
| 提交后长时间停在「待审批」 | 每天汇总一次未处理的申请，提醒审批人 |
| 审批人「退回申请」或配置人「退回修改」 | 按 6.5 在群里公告退回条目及原因，@ 配置负责人处理。需要申请人补充时，在群里列出要补的内容 |
| 进入 iBoss 操作失败对应的状态 | 立即在群里报警 |
| 进入「生效政策」 | 在原汇报卡片上标记「已生效」，形成从邮件到生效的闭环 |

实现方式待定：读取机器人账号的「流程待办 → 抄送」通知，或定时查询机器人所建记录的「政策状态」。当前账号**没有权限查看工作流运行详情**（点开报「工作表字段权限错误」），所以只能看状态、看不到每一步的细节。

**测试单删除（D15）**。机器人仅在群卡片有效同意后建单，并按 D15 对符合条件的自建测试单执行官方接口删除。人工在明道云提交、撤回及处理退回。删除可能触发的重算效果仍待实测。

**副作用：新建一条政策会连带重算同国家的其他政策**

新建 1 条测试记录时，生成 iBoss 接口参数的工作流以申请人身份运行了 **20 次**，涉及测试记录 1 条和同一国家的 19 条真实政策。推测是新政策进入了同国家的「同期有效优惠政策」，触发相关政策重新生成 iBoss 接口参数。具体改了哪些字段，因权限所限**未知**。

由此带来两条约束：
1. **不能随手在正式表里建测试记录。** 真实测试建单须经产品负责人同意并通知审批人与配置人（机器人不提交的测试单，经产品负责人同意可免事前通知，须在授权登记里留免通知记录），经群卡片有效同意后才发建单请求；测试单删除按 D15。
2. 新建政策会触发工作流并重算同国家政策，产品负责人已接受 X5 的这一副作用。请求须保留平台正常的工作流行为。

**测试记录的去向**：录制时创建的 1 条测试记录已不在任何视图中，按记录 ID 打开也无法显示，推测已被删除，删除人未知。产品负责人决定不再核对受重算影响的 19 条政策（2026-11-18）：此类重算在任何人新建同国家政策时都会发生，测试记录删除后下一次重算即不再包含它。

### 10.4 明道云「优惠政策申请」表的实际结构（2026-11-18 页面观察）

在已登录的浏览器中打开一条记录看到的结构，只读未改。字段 ID、类型、可选值在录制新建记录的请求时确认（10.3）。

**视图（即政策状态的流转）**：新建 → 待审批 → 待配置 → 配置完成 → 生效政策；另有 iBoss 创建完成待上架和操作失败对应的视图。机器人经有效同意建单后，单据停在「新建（运营中心）」，由人工提交进入「待审批」（D7）。

**记录上的按钮**：每条记录顶部有「提交申请」按钮；列表页可勾选多条后提交，每条记录各发起一个审批（用户确认）。

**字段**

| 分组 | 字段 | 说明 |
|---|---|---|
| 顶部 | 优惠政策名称 | 机器人取本条唯一且确定的用户标签名（6.2） |
| | 是否需要维护互斥组 | 是／否。选「否」时政策自动创建并上架、直接生效；表单提示「需要互斥组的情况不要选否」 |
| | 政策状态 | 如「新建（运营中心）」 |
| 基本信息 | 公司名称 | 机器人按申请国家查私有对照表（6.2、R10） |
| | 政策类型 | 如「定向政策」 |
| | 开始日期、结束日期 | |
| | 优惠方式、优惠类型 | 如「赠送时长」 |
| | 是否只触发一次 | 是／否 |
| | 降包用户取消优惠 | 是／否（对应会议中的「是否限制降包用户」） |
| 优惠信息 | 充值天数、赠送天数 | 如充 30 送 30 |
| | 多买多送 | 是／否 |
| | 生效倍数 | 数字 |
| 节目包（子表） | 当前节目包、当前节目包价格计划、赠送节目包 | 按 6.2 逐行核对，价格计划由表单带出 |
| 用户标签（子表） | 标签名称、处理成功用户数 | 影子标签名为原标签名加 `_image` 后缀 |
| 标签汇总 | 标签与适用条件关系、标签总用户数、目标标签数量、标签最早开始日期、标签最晚结束日期 | 多为根据子表自动计算，机器人应无需填写（待确认） |

**对设计的影响**

- 机器人按 6.2 填写节目包子表和用户标签。表单支持多选标签，自动取政策名称时须能确定唯一标签。
