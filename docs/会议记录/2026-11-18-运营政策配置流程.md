## 一、演示内容：优惠政策配置的现行流程

配置负责人演示了一批定向召回政策（共 6 条）从申请到上线的完整操作。

### 1. 申请与存档

- 各国运营通过**邮件**提交政策申请。
- 邮件存入按活动类型、大区、国家、年份和操作日期归类的归档目录（日期页合成示例 `2030.0615`），并把政策明细粘贴进去。
- 存档用于日后查找政策和历史记录。
- 〔会后核实〕归档目录位于运营团队的飞书知识库，存档页链接即明道云「任务审批链接」的值，详见产品文档 6.7。

### 2. 在明道云录入政策

一条政策录一条记录，演示中提到的字段和操作规则：

| 字段 | 规则 |
|---|---|
| 国家 | 输入国家编码，或在下拉列表中选择 |
| 用户标签 | 标签需已在 CRM 建好；录入前先看标签是否生效 |
| 是否维护互斥组 | 默认选「是」 |
| 政策类型 | 本例为「定向」 |
| 生效日期 | 不能早于配置当天。当天超过 BOSS 配置截止时间时，开始日期顺延至次日。以合成日期举例，申请周期为 2031-04-08 至 2031-04-25，2031-04-11 配置时可当天生效，超过截止时间则顺延至 2031-04-12。 |
| 优惠类型 | 「充一月送一月 / 买一赠一」选「赠送」，可多次触发 |
| 是否限制降包用户 | 申请写「不限制用户升降包」时选「否」 |
| 赠送节目包 | 赠送只能以附属包形式发放，系统里是原节目包的 copy，0 元计费 |
| 适用条件 | 必填，一般写「休眠用户召回」 |
| 审批件 | 附申请邮件截图 |

补充说明：

- **影子标签**：「外呼且接通且愿意参加」这类活动，用户需点击确认按钮。配置时用影子标签，初始用户数为 0，用户每确认一次就进一个；优惠绑定在影子标签上，前台显示的仍是原标签。这类活动**一次只能选一个标签**，其他活动可以选多个。
- **连续录入**：同一批政策结构相似，用「保留本次提交并继续创建」连续录入。
- **草稿模板**：配置负责人会把常用配置（如定期更新的政策）存成草稿模板，每次改标签后复用。所以列表里有几条用户数完全一样，属于正常情况。

### 3. 自查

录完看一遍列表。不同标签的用户数通常不同；如果两条政策用户数一样，要检查是否选重了标签。

### 4. 审批与同步

- 政策审批人审核，确认无误后点击通过。
- 审批通过后，政策**自动从明道云同步到 BOSS**，不需要再手工录一遍。

### 5. 在 BOSS 配置优先级

- 路径：产品 → 单笔优惠实例 → 选国家 → 状态筛选「待上架」和「有效」→ 调整优先级。已失效和过期的政策不用管。
- 优先级在**用户触发时**起作用：触发时按优先级，找第一条满足条件的政策发放。

## 二、工作量与痛点

- 演示批次：6 条。
- 平时每月：估计 30～50 条。
- 圣诞活动：一次配了 100 条；当前有效政策共 102 条。
- 痛点：配置量大、耗时，**有时不能及时上线**。
- 会上估算：交给 agent 后每月至少节省 20 小时。
- 风险评估：配置出错的后果相对可控，有人守着，不会造成严重故障。

## 三、讨论：申请入口的两种方案

| | 方案 A：继续用邮件 | 方案 B：改填多维表格表单 |
|---|---|---|
| 申请人怎么提 | 照旧写邮件，异常和特殊需求写在邮件里 | 直接填表单 |
| 谁写入系统 | agent 读邮件后录入，表格只有 agent 写 | 表单数据直接入库，不再需要邮件 |
| 好处 | 灵活，申请人不需要学新东西 | 申请和记录集中在一处，数据结构化 |
| 问题 | agent 需要从自由文本中识别字段 | 需要培训各国运营学会填表 |

会上结论：从 AI 能力看两种都可行，区别不大，**会上未定**。

## 四、参照案例：传媒「编单」项目

项目介绍人介绍了正在做的另一个项目，作为难度对比：

- 任务：根据频道每月的 EPG（节目计划），由 AI 生成精确到帧的播出单。差一帧，屏幕就会黑屏。
- 难点：广告、宣传片的插播规则有固定的也有灵活的，素材时长经常变，写死的程序无法覆盖所有情况，所以需要 AI。
- 约束：必须内网部署，不能连互联网；有时效要求，播出单需提前 48 小时产出。
- 结论：相比之下，政策配置更简单，填错了也不是严重问题。

## 五、会议结论

1. 政策配置是运营中心当前最主要的堵点，确定用 AI agent 解决。
2. 申请入口（邮件或表单）会上未定，会后另行决定。
